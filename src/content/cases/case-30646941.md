# 계약 기반 에이전트 핸드오프 — 에이전트끼리 대화시키지 않는다

## 주장

멀티에이전트가 실무에서 무너지는 지점은 모델 성능이 아니라 **인터페이스**다.
에이전트끼리 자연어로 넘기게 두면 (1) 키 이름이 어긋나고 (2) "했습니다"라는 자기보고가 진실처럼 굳고 (3) 어디서 깨졌는지 추적이 안 된다.

**해법: 에이전트끼리 대화시키지 않는다. 파일 계약만 준다.**

## 규칙 4개

1. **문서 하나가 유일한 인터페이스 정본** (`CONTRACT.md`).
   각 스테이지의 입력·출력 경로와 **JSON 키 이름을 문자 그대로** 못박는다. "임의로 바꾸지 말 것"을 명시한다.
2. **산출 파일이 유일한 진실.** 에이전트의 보고문은 판정에 반영하지 않는다.
   → 검수자는 보고서를 읽지 않고 **파일을 연다**.
3. **판정 형식을 고정한다.** 마지막 줄이 정확히 `판정: PASS` 또는 `판정: FIX_REQUIRED`.
   자유 서술로 두면 자동화가 판정을 못 읽고, 애매한 통과가 생긴다.
4. **검수 항목에 번호를 박고 대체를 금지한다.**
   → [[검수가_잡아낸_것들]] 의 1번 사고가 정확히 이걸 안 해서 났다.

## 왜 대화보다 파일이 나은가

| | 대화 핸드오프 | 파일 계약 |
|---|---|---|
| 어긋남 감지 | 사람이 읽어야 앎 | `json.load` 가 즉시 실패 |
| 재현 | 불가 (세션 소실) | 파일이 남아 언제든 재검수 |
| 병렬 | 순서 얽힘 | 같은 입력을 N개가 동시에 소비 |
| 책임 소재 | 모호 | 어느 파일이 계약을 어겼는지 특정 |

## 병렬 팬아웃과의 궁합

같은 `brief.json` 을 3개 워커가 동시에 읽고 **각자 자기 폴더에만 쓴다**(`02_build/<key>/`).
입력이 파일이라 경합이 없고, "다른 안 폴더를 건드리지 마라" 한 줄로 충돌이 막힌다.

## 함정

- **계약을 줘도 응답 키는 어긋난다.** 통합 시 *생산 키 ↔ 소비 키* 를 기계로 대조하는 절차가 따로 필요하다.
- **검수자도 계약을 어긴다.** 검수 항목을 자기 마음대로 재구성한다 → 번호 고정 + 대체 금지를 명문화.
- **워커에 붙은 훅이 도구 호출을 막을 수 있다.** 파이프라인 워커는 오케스트레이터용 게이트 훅을 벗겨야 한다.
