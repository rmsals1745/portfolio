# JUST DESIGN — 에이전트가 홈페이지 시안 3안을 만들고 스스로 검수·수정한다

> **한 줄**: 사람이 지시 한 번 하면, 서로 대화하지 않는 에이전트 3인이 **같은 소재로 취향이 다른 홈페이지 시안 3안**을 만들고, 검수자가 기계 대조로 판정하고, 걸린 곳을 다시 고쳐 통과시킨다.

**산출물**: `C:\Users\admin\Projects\justdesign`
**바로 열기**: `02_build\a\index.html` · `02_build\b\index.html` · `02_build\c\index.html`
**계약 정본**: `CONTRACT.md` (v4)

![[justsite_3안비교.jpg]]

## 1. 왜 만들었나

인생딸깍에 **홈페이지 1:1 제작 서비스**를 붙이기로 했다. 그 전에 두 가지를 증명해야 했다.

1. 이 일이 **에이전트로 굴러가는가** (사람이 매번 붙어야 한다면 서비스가 아니라 외주다)
2. 클라이언트에게 **"취향대로 만들어 드립니다"를 말이 아니라 화면으로** 보여줄 수 있는가

두 번째가 영업의 핵심이다. 소상공인은 "어떤 스타일 원하세요"라는 질문에 답하지 못한다. **먼저 몇 안을 내밀어야 대화가 시작된다.**

## 2. 구조 — in → fn → out

에이전트의 실체는 **Hermes 프로필**이고, 순서 강제는 **kanban 태스크 의존성**이다. 보드 `justdesign`.

| 스테이지 | 에이전트 | 모델 | 하는 일 | 산출(계약) |
|---|---|---|---|---|
| **in** | Ivy | glm-5.2 | 가상 브랜드·상품·사진 프롬프트·**취향 3안** 설계 | `01_brief/brief.json`, `styles.json` |
| **fn** | Finn ×3 **병렬** | glm-5.2 | 배정받은 취향 1안의 HTML 제작 | `02_build/{a,b,c}/index.html` |
| **out** | Otto | mimo-v2.5-pro | 9항목 기계 대조 → 판정 | `03_review/REVIEW.md`, `verify.json` |
| **revise** | Finn | glm-5.2 | 지적/피드백 반영 | 해당 안 덮어쓰기 (직전본 백업) |

**핵심 설계 = 소재는 하나, 취향만 갈린다.**
브랜드명·상품 9종·가격·주소·사진이 세 안 모두 **완전히 동일**하다. 달라지는 건 팔레트·여백·타이포·그리드뿐이다.
그래야 클라이언트가 "내용"이 아니라 **"스타일"을 고르게** 된다. 이걸 검수 9번 항목으로 **기계 확인**한다.

→ 방법론: [[in_fn_out_파이프라인]] · [[계약기반_에이전트_핸드오프]]

## 3. 소재는 전부 우리 것 (저작권이 깨끗하다)

포트폴리오라 남의 자산을 쓸 수 없다.

- **상품 사진 10장** — 로컬 ComfyUI + Z-Image-Turbo 로 직접 생성 (`tools/render.py`).
  첫 장은 모델 로딩 포함 447초, 이후 장당 4~5분. 총 10장 2,670초.
- **지도** — 여기가 판단이 갈린 지점이다. 구글 지도 iframe 대신 **실제 OpenStreetMap 타일을 받아 핀을 찍어 로컬 PNG 로 구웠다** (`tools/map.py`).
  - 진짜 지도다(실제 성수동2가 골목·도로명), 가상 주소만 핀으로 얹었다.
  - **오프라인에서도 보인다** — 시안을 USB·이메일·노트북으로 들고 가서 열어도 지도가 뜬다. iframe 이면 클라이언트 앞에서 빈 박스가 뜰 수 있다.
  - ODbL 라이선스 의무인 `© OpenStreetMap contributors` 표기를 이미지와 화면 양쪽에 남겼다.

## 5. 검수 9항목 (계약 v2)

1 계약 키 존재 · 2 상품명 전수 렌더 · 3 이미지 실참조+디스크 실재 · 4 외부 리소스 0(iframe 포함) · 5 섹션 id 5개 · 6 charset/lang/viewport · 7 **시크릿 노출 0** · 8 alt·자리표시자·지도/저작자표기 · 9 **소재 동일성 + 팔레트 상이**

번호를 계약에 고정한 이유: 1사이클에서 검수자가 **자체 항목을 만들어 시크릿 점검을 빠뜨렸다.** "9항목을 이 번호 그대로, 자체 항목으로 대체 금지"를 명문화해 막았다.

## 8. 3사이클 — 입구가 생겼다 (계약 v3, 2026-08-12)

앞의 두 사이클은 *내가* "베이커리 만들어"라고 지시했다. 3사이클부터는 **클라이언트가 채운 상담지 한 장이 파이프라인 전체를 굴린다.**

![[justsite_인테이크폼.png]]

**인테이크 폼** `00_intake/intake_form.html` — 소상공인이 채운다는 전제로 설계했다.
- 디자인 용어를 묻지 않는다. 취향은 **색 스와치 카드를 눈으로 고른다**(무드 6종).
- 모르는 칸은 비워도 된다 — 비면 우리가 채우고, 채운 사실을 `notes` 에 남긴다.
- 사진이 없으면 우리가 만든다.
- **"피하고 싶은 느낌"** 을 따로 받는다. 이게 3안을 벌릴 때 **금지선**이 된다.

폼은 **실제 브라우저에서 타이핑·클릭해 채워** `intake.json` 을 뽑았다(손으로 JSON 을 쓰면 폼이 작동한다는 증명이 안 된다).
⚠️ 다만 **다운로드 버튼 자체는 헤드리스에서 파일이 안 떨어져 미검증** — `#out` 값으로 우회 저장했다.

**실측 — 클라이언트 입력이 지켜졌는가** (가상 클라이언트: 골목 꽃집 · 연남동 · 상품 8종)

| 검사 | 결과 |
|---|---|
| 상호·상품명 8개·가격 8개·전화·주소·인스타 | **글자 그대로** ✅ |
| 빈 칸(tagline) | 우리가 지음 + `notes` 명시 ✅ |
| `avoid` = "너무 어둡거나 무거운 건 싫어요" | **3안 전부 밝은 계열** ✅ |
| `musts` 6개(지도·전화·영업시간·상품·인스타·예약) | 3안 모두 실재 ✅ |
| `photos.mood` = "밝고 화사하게, 아침 햇빛" | 생성 사진에 반영 ✅ |

**주목할 결과**: 2사이클에서 완성도가 가장 높았던 **"모던 다크"가 이번엔 아예 제안되지 않았다.** 클라이언트가 어두운 걸 싫다고 했기 때문이다. *우리 취향보다 클라이언트 말이 위*라는 것이 계약으로 강제된다.

![[justsite_꽃집_3안비교.jpg]]

**revise**: r1 PASS → R2 취향 피드백(오늘의 꽃 띠·부가세 포함·화환 당일배송 표시·전화 상시노출) → **r2 PASS**. 요구 4건이 3안 전부에 반영된 것을 기계 확인.
그리고 [[검수가_잡아낸_것들]] 의 3번(백업 누락)을 **검수 11번 항목으로 번역**했고, 이번엔 `index.r1.html` 이 3안 모두 존재한다 — **계약 조항을 검수 항목으로 옮기면 실제로 지켜진다**는 증거.

## 9. 발견한 한계 — 시안이 서로 비슷하다

3사이클을 보고 사장이 지적했다: *"디자인이 다 비슷비슷한데."* 재보니 사실이었다.
→ 원인과 처방은 [[시안_다양성은_계약이_막고_있었다]] 로 분리했다. 요약: **내가 계약에 섹션 5개와 순서를 고정해 박았고, 그것이 검수 항목이기까지 해서 다르게 만들면 떨어졌다.**
