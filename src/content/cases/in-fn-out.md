# in → fn → out — 조직을 함수처럼 짠다

## 골격

**부서 = 파이프라인, 팀 = 한 스테이지.** 자동화 함수 모델을 그대로 조직 구조로 올린 것.

- **in** — 트리거 + 소재 (수집·기획·리서치)
- **fn** — 생성·가공 (제작)
- **out** — 검수 + 배포 + 결재

팀 간 핸드오프는 **파일 계약**뿐이다 → [[계약기반_에이전트_핸드오프]]

## 왜 이 3분할인가

역할을 나누는 축은 여러 개일 수 있지만, **"만든 놈이 검사하면 안 된다"** 는 제약이 out 을 강제로 떼어낸다.
그리고 소재 확보(in)를 제작(fn)에서 떼면 **같은 소재로 여러 안을 병렬 생성**할 수 있게 된다 — 이게 시안 N안 제시의 구조적 근거다.

```
        ┌──────────── 같은 소재 ────────────┐
in ─────┤                                   ├─── out (검수·판정)
        └── fn(a) ── fn(b) ── fn(c) 병렬 ───┘        │
                                                  FIX_REQUIRED
                                                     │
                                                  revise → 재검수
```

## 실행 수단 매핑

| 팀 유형 | 실행 수단 |
|---|---|
| 텍스트·기획·제작 | 헤드리스 에이전트 워커 (프로필 + 태스크 보드) |
| **도구 실행**(렌더·촬영 등) | MCP 또는 오케스트레이터 직접 실행 — 헤드리스 워커는 **터미널 타임아웃**에 걸린다 |
| 검수·배포·결재 | 별도 모델의 검수자 → 사람 결재 |

> 실측 함정: 워커의 터미널 타임아웃이 180초라 **장당 4분짜리 이미지 렌더를 워커가 직접 돌리면 죽는다.**
> 워커는 *작업목록(JSON)만 만들고*, 긴 도구 실행은 오케스트레이터가 배치로 돌리는 게 맞다.

## 셀프리뷰 금지

그 라운드에 산출물을 낸 모델은 검수 후보에서 제외한다. 검수자가 없으면 **자동 통과가 아니라 사람에게 올린다.**
