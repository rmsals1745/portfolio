대표 시스템

줄을 누르면 펼쳐집니다

  1. 왜 만들었나

    AI 산출물은 그럴듯하게 틀립니다. 사람이 매번 들여다봐야 한다면 자동화한 의미가 없습니다. 그런데 같은 모델이 만들고 같은 모델이 검수하면, 대개 그냥 통과합니다.

    어떻게 막았나

    • 구현하는 AI와 검수하는 AI를 서로 다른 회사의 모델로 나눴습니다.
    • 그 라운드에 결과물을 낸 모델은 검수 후보에서 자동으로 빠집니다. 후보가 다 떨어지면 자동 승인이 아니라 사람에게 넘깁니다.
    • 판정은 approve · revise · reject 세 단어로만 받습니다. 형식을 어기면 엔진이 다시 묻습니다 — 애매한 말을 승인으로 읽지 않기 위해서입니다.
    • 워커의 자기보고는 믿지 않습니다. 실제로 바뀐 코드(diff)만 판정에 씁니다.

    실제로 돌려 보니

    2026년 7월 18일부터 8월 9일까지 기록된 52번의 실행 가운데 17번에서 검수 AI가 실제로 수정을 요구했고, 그중 16번은 두 번 이상 고쳐서 다시 냈습니다. 검수가 장식이 아니었다는 기록입니다.

    알아낸 것

    타입 검사 같은 관문은 워커가 아무 일도 안 해도 통과합니다. 그래서 손대기 전 코드에서도 통과하는 검사를 따로 가려내, 그런 통과는 “아무것도 안 깨졌다”까지만 뜻한다고 검수자에게 알립니다.

    Python · Claude Code CLI · GLM · MiMo · DeepSeek · Kimi

  2. 무엇을 하나

    설문지 대신 상담형 에이전트가 마주 앉아 가게와 상품 이야기를 인터뷰합니다. 그 답을 씨앗 삼아 네이버 블로그 원고를 만들고, 인스타그램·쓰레드·X 용 원고는 각 작성창까지 실어 보냅니다. 업종을 가리지 않는 범용 도구입니다.

    자동발행 기능은 일부러 없앴습니다. 사용자가 통제권을 잃는 자동화는 편리한 게 아니라 불안한 것이었습니다.

    돈이 걸린 코드

    • 결제사가 되돌려 주는 주소가 예상과 다르게 붙어 돈은 빠졌는데 지급은 안 되던 사고가 있었습니다. 지금은 브라우저에 기대지 않고, 서버가 결제 알림의 서명을 확인하고 → 결제 건을 다시 조회하고 → 같은 지급이 두 번 나가지 않게 막는 세 겹으로 결론을 냅니다.
    • 상품 가격표를 서버 한 곳으로 모아, 화면과 서버의 가격이 어긋날 수 있는 구조 자체를 없앴습니다.
    • 서비스를 멈추지 않은 채 데이터베이스 구조를 40차례 바꿔 왔습니다.

    끝까지 간 것

    이용약관 · 개인정보처리방침 · 청약철회와 환불규정 · 사업자등록 · 통신판매업신고까지 갖췄습니다. 시연용이 아니라 결제를 받을 수 있는 형태로 끝냈습니다.

    Cloudflare Pages Functions · D1 · React · Capacitor · PortOne V2

  3. 구조

    소재 기획 → 제작(세 안을 동시에) → 검수. 에이전트끼리 대화시키지 않고 파일 계약으로만 주고받습니다. 상호·상품·가격·주소는 클라이언트가 적은 그대로 두고 디자인 방향만 바꾸기 때문에, 클라이언트는 내용이 아니라 스타일을 고르게 됩니다.

    검수가 실제로 막아낸 것

    제작 AI 셋이 모두 지도 지시를 무시하고 CSS와 이모지로 “지도처럼 보이는 것”을 그렸습니다. 눈으로는 통과할 화면이었습니다. 파일이 실제로 무엇을 참조하는지 기계로 대조해 잡았고, 한 번 고친 뒤 9개 검사를 세 안 모두 통과했습니다.

    그 앞 판에서는 검수 AI가 검사 항목을 스스로 바꿔 짜면서 비밀키 노출 점검을 통째로 빠뜨리고 합격을 냈습니다. 그 뒤로 항목을 번호째 고정했습니다.

    알아낸 것

    무엇을 잴지를 검수자가 정하게 두면, 검수는 죽은 채로 통과합니다.

    시안에 들어간 상품 사진 8장은 외부 서비스 없이 로컬 확산모델로 직접 만들었습니다.

    멀티에이전트 오케스트레이션 · 파일 계약 · 판정 프로토콜 · ComfyUI

  4. 구조

    • 에이전트가 필요 없는 반복 작업 14개를 중앙 게이트웨이에서 떼어 운영체제 스케줄러로 내렸습니다. 게이트웨이가 재시작되거나 죽어도 상관없이 돕니다.
    • 세션이 시작되면 작업 맥락을 넣고 자동으로 커밋하며, 끝나면 배운 개념을 뽑아 쌓습니다. 사람이 기억해야 할 일을 런타임이 대신 기억합니다.
    • 원격 서버에 워커를 상주시켜, 로컬 기계가 꺼져 있어도 메신저 → 서버 에이전트 → 커밋 → 결재 흐름이 이어집니다.
    • 백업은 로컬 · GitHub · 클라우드 세 곳에 둡니다.

    알아낸 것

    API가 결제 오류를 뱉을 때 “충전이 부족하다”고 믿고 시간을 버렸습니다. 진짜 원인은 설정 파일마다 남아 있던 낡은 주소였습니다.

    그 뒤로 흩어진 키를 한 곳으로 모아, 교체할 때 파일 하나만 고치면 되게 바꿨습니다.

    Python · Docker · systemd · cron · Windows 작업 스케줄러 · Telegram Bot API
