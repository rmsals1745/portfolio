2026.04 — 지금 · 설계·구현 단독

justswarmAI 여러 대를 한 팀으로 묶는 엔진

문제

AI가 낸 결과는 그럴듯하게 틀립니다. 같은 AI가 만들고 같은 AI가 검사하면 그냥 통과합니다.

지은 것

한 AI가 코드를 짜면 다른 회사의 AI가 검사하고, 통과할 때까지 되돌려 보내는 엔진. 자기 결과를 스스로 통과시키는 길을 구조적으로 막았습니다.

결과

52번 실행 중 17번에서 검사 AI가 실제로 고치라고 돌려보냈습니다 — 검사가 장식이 아니라는 뜻입니다.

구조

  • 만드는 AI와 검사하는 AI를 다른 회사 모델로 분리 — 판정은 approve · revise · reject 세 단어만 받습니다. 형식을 안 지키면 엔진이 다시 묻습니다.
  • 셀프리뷰 차단 — 그 판에서 결과물을 낸 모델은 검사 후보에서 자동으로 빠집니다. 후보가 다 떨어지면 자동 승인 대신 사람에게 넘깁니다.
  • 한 곳이 죽어도 안 멈추는 대체 순번 — 장애 · 안전필터 거부 · 글자 깨짐을 서로 다른 실패로 나눠 다음 모델로 넘깁니다.
  • AI의 자기 보고는 믿지 않습니다 — 실제로 바뀐 코드(diff)만 판정에 씁니다.

검사가 잡아낸 것

셀프리뷰 가드를 넣기 전엔 검사자 없이 승인된 실행이 2번 있었습니다. 가드를 넣은 뒤 103번 실행에서는 한 번도 없었습니다. 또 "타입 검사 통과" 같은 신호는 AI가 아무 일도 안 해도 통과한다는 걸 발견해, 작업 전 상태에서도 통과하는 검사를 가려내는 장치를 넣었습니다.

Python · Claude Code CLI · GLM · MiMo · DeepSeek · Kimi

인생딸깍AI가 블로그·SNS 글을 대신 써주는 월 구독 서비스

문제

홍보 글은 누구에게나 필요하지만, 매번 쓸 시간과 요령이 없습니다. 무엇을 써야 할지부터 막힙니다.

지은 것

AI가 먼저 인터뷰로 이야기를 캐낸 뒤 글을 쓰고 네이버 블로그 발행까지 잇는 서비스. 결제 · 환불 · 약관 · 사업자 요건까지 혼자 갖췄습니다.

결과

첫 줄을 쓴 지 4개월 만에 실제로 돈을 받는 서비스가 됐고, 운영을 멈추지 않은 채 데이터베이스 구조를 40번 고쳤습니다.

어떻게 돌아가나

  • 설문지 대신 인터뷰 — 마스코트 「딸깍판다」가 마주 앉아 묻고, 옆 칠판에 상담 진행률과 "꼭 필요한 것 / 있으면 좋은 것"이 채워집니다.
  • 질문은 전부 객관식 카드 — "손님이 주로 어디서 오세요?" 같은 답에 따라 글의 전략이 갈립니다.
  • 하나의 씨앗에서 여러 채널 — 블로그는 발행까지, 인스타그램 · 쓰레드 · X 는 원고를 만들어 작성창까지 실어 보냅니다. 올리는 손가락은 사용자 것으로 남겼습니다.

결제 안전망

결제사 서명 검증 · 단건 재조회 · 중복 지급 방지, 세 겹으로 이중결제와 누락을 막습니다. 요금제는 월 구독 하나입니다.

Cloudflare Pages Functions · D1 · React · Capacitor · PortOne V2

2026.08 · 설계·배선·검증 단독

JUST DESIGNAI가 만들고 AI가 검수하는 홈페이지 시안 공장

문제

AI에게 시안을 여러 개 시키면 다 비슷하게 나오고, 눈으로만 검수하면 그럴듯한 가짜에 속습니다.

지은 것

상담지 한 장을 받으면 AI 세 명이 방향이 다른 시안 3개를 동시에 만들고, 검수 AI가 파일을 기계로 대조해 합격을 판정하는 파이프라인.

결과

제작 AI 셋이 모두 진짜 지도 대신 "지도처럼 보이는 그림"을 그렸는데, 검수가 이를 잡아냈고 수정 뒤 27개 항목을 전부 통과했습니다.

구조

  • 기획 → 제작(3안 병렬) → 검수 세 단계. AI끼리 대화시키지 않고 파일 계약으로만 주고받습니다.
  • 내용은 같고 디자인만 다르게 — 상호 · 상품 · 가격 · 주소는 고객이 적은 그대로. 고객은 "내용"이 아니라 "스타일"을 고릅니다.
  • 사진도 안에서 — 상품 사진 8장을 로컬 확산모델로 직접 생성했습니다. 지도는 실제 지도 타일을 받아 이미지로 구웠습니다.

알아낸 것

검수자가 검사 항목을 스스로 줄이자 비밀키 노출 점검이 통째로 빠진 채 통과가 났습니다. 그래서 "항목을 이 번호 그대로, 대체 금지"를 계약에 박았습니다. 무엇을 잴지를 검수자가 정하면, 검수는 죽은 채로 통과합니다.

멀티에이전트 오케스트레이션 · 파일 계약 · ComfyUI · OSM 타일 합성

2026.05 — 지금 · 설계·구현 단독

Hermes 상시 런타임PC가 꺼져 있어도 예약한 일이 굴러가는 바닥

문제

작업 PC는 대부분 꺼져 있습니다. 시간 맞춰 도는 자동화는 기계가 꺼진 동안 조용히 건너뛰고, 아무도 모릅니다.

지은 것

에이전트가 필요 없는 반복 작업 14개를 중앙에서 떼어 OS 스케줄러로 내리고, 원격 서버에 상주 워커를 두고, 백업을 세 곳에 나눴습니다.

결과

중앙이 죽거나 PC가 꺼져 있어도 각자 돌고, 놓친 일은 기계가 켜지는 순간 따라잡습니다.

구조

  • 중앙과 스케줄 분리 — 놓친 실행을 켜지는 순간 다시 도는 설정으로, 중앙 재시작 · 크래시와 무관하게 굴러갑니다.
  • 이벤트 훅 — 세션 시작 때 작업 맥락 주입과 자동 저장, 끝날 때 배운 개념 추출. 사람이 기억할 일을 런타임이 대신 기억합니다.
  • 원격 상주 — 메신저 → 서버 에이전트 → 코드 반영 → 결재가 PC 없이 진행됩니다.
  • 백업 세 곳 — 로컬 · GitHub · 클라우드.

알아낸 것

AI 서비스가 결제 오류를 낼 때 "충전이 부족한가" 싶어 시간을 버렸는데, 실제 원인은 프로필마다 흩어진 설정에 남은 옛 주소였습니다. 그 뒤로 키를 한 곳에만 두게 다시 설계했습니다.

Python · Docker (Caddy · CouchDB) · systemd · cron · Windows 작업 스케줄러
